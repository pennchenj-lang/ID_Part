# HPID-Split 中文说明

HPID-Split 接收一张资产图片，输出互不重叠、具有父子关系且可审计的
Part ID。它面向角色、道具、物品、设备、家具、车辆、自然物和场景资产，
核心不是重新包装基础模型，而是融合候选、处理冲突、确定像素所有权并生成
稳定 ID。

当前输出分为两层：`Part ID` 保留细粒度候选，便于检查与局部编辑；`Group ID`
只保留经过主体连通性、对象部件清单和结构证据确认的物理编辑组。颜色、明暗、
纹理和原始 SAM2 区域只作为内部证据，不能单独成为最终编辑组。刀具清单会把
护手和尾端并入刀柄，并通过长轴宽度瓶颈与相对材质变化区分刀刃、刀柄和缠布；
该过程不使用固定颜色、图片坐标或文件名规则。

公开 `Group ID` 采用严格串行的三重验证：先确认对象类别与允许的语义部件，
再确认包含关系、连通性、形状和拓扑结构，最后才用颜色、明暗、纹理和边缘闭合
做复核。后一重不能补救前一重失败，外观证据也不能单独创建 ID。对于手机屏幕
这类内嵌表面，语义候选只提供“屏幕”名称，实际像素边界必须来自独立通过结构
与非高光检查的封闭面板候选。

`v0.3.4` 将常见资产的最终分组改为“主体残差宿主”所有权。瓶身、壶身、车身、
椅架或剪刀把手先作为保守宿主；盖子、标签、把手、座面、刀刃、车灯和车窗只有在
语义与结构均通过后才占用自己的局部像素，其余前景全部回到宿主。同名候选先做
跨来源共识聚类，因此单个过宽候选不能压过多个相互一致的候选。椅子中位于中轴、
横向展开的构件可由结构证据纠正为座面；车辆挡风玻璃只能在车顶和引擎盖限定的
结构槽内恢复。外观证据只能扩展已确认标签或刀刃的边界，高光、阴影、颜色块和
纹理块仍不能创建或命名 ID。本版本新增六类未经人工修补的定性审计，但不改动
`v0.3.1` 冻结的 226 例定量结果。

`v0.3.5` 在已确认语义种子之后增加物理边界恢复：包裹式标签可沿闭合标签带补全，
椅面可在靠背与椅架限定的结构槽内恢复完整坐垫；车辆格栅不再并入保险杠，并由道路
车辆清单、下缘轮廓和左右成对结构恢复两个车轮。平滑后的 Lab 外观只用于把已准入
部件贴合到图像接缝，高光和阴影仍不能创建 ID。冻结候选上的 226 例重分组审计全部
完成，未重新运行候选推理，也未改动细粒度 Part-ID 图；论文的冻结定量结论保持不变。

`v0.3.6` 在补边前先区分局部贴纸与环绕标签。同一个标签候选不能再把自己当成独立
的环绕证据；环绕标签必须先得到另一条结构候选支持，再在已验证槽内逐列寻找真实的
上下边缘。道路车辆还会把断开的狭长车身残余并回相邻的已验证表面，避免输出任意横向
色带。本次只在冻结候选包上重做分组回归，不重新运行候选推理、不改细粒度 Part-ID 图，
也不替换 `v0.3.1` 冻结的定量结论。

`v0.3.7` 不再让过宽的结构支持候选直接占有环绕标签像素。已验证的标签种子作为确定
前景，独立通过的支持候选只定义可能前景槽，再在槽内执行受限材质切分。道路车辆中的直接验证
保险杠与成对结构车轮会在通用边界细化前锁定，避免外观分水岭把它们扩张到车身或轮拱。
226 个冻结候选包的编辑组 F1@.25 保持 `0.3773`；平均匹配 IoU 从 `0.46415` 变为
`0.46439`，平均边界 F1 从 `0.49015` 变为 `0.49045`。肥皂液瓶标签例的 IoU / 边界 F1
由 `0.6827 / 0.7813` 提升到 `0.8363 / 0.9176`。本次不重跑候选模型，分组时不读取真值，
且不改动 `v0.3.1` 的冻结主结论。

## 两种拆分模式

### 自动模式

用户只需上传图片。`Fast` 自动模式先运行一次整图 SAM2 候选池，再复用同一批
蒙版发现资产根和内部部件；清晰的独立物体还会通过画面边界估计前景，只有找不到
连贯根区域时才回退到 Grounding DINO。最终融合按三级证据排序：对象类别锁定的
语义部件清单优先，轮廓、连通性、长轴与结构瓶颈负责确认边界，颜色、亮度和纹理
只用于细化或解决归属平局。需要精确语义定位的少数类别会自适应执行一次定向
Grounded-SAM2，而普通类别不承担这项耗时。材质证据只是 RGB 外观代理，不代表
真实物理材质识别。

枪械清单先由长轴拓扑确定枪口组件、枪管组件、护木、机匣、弹匣、握把和枪托七个
语义种子。只有得到语义和结构共同支持的前护木种子，才会建立平滑 Lab 材质参考；
其中亮度权重被降低，使同一护木的高光面和阴影面可以重新连通，再由保边分水岭贴合
装配接缝。颜色、反光和纹理不能单独新增编辑组。

角色分组沿检测到的头部到脚部姿态轴计算，而不是按图片纵坐标硬切。上装与下装的
分界由头部结束位置和鞋类开始位置共同推导；位于头部内部的孤立头发岛会经过拓扑
审计，成对且与已确认皮肤一致的小腿区域也可从过宽鞋类候选中退回身体。外观证据只
能修正已有物理清单的归属，不能单独创建新组。

多尺度外观候选会分别为小细节、中型部件和大型结构保留名额，避免高对比度碎片占满
候选池。闭合轮廓与包围区域用于恢复镜片、屏幕、门板和框内结构；位于完整面板内部、
仅由纹理或反光形成的细碎区域会被抑制。同类证据可以合并同一物理区域的碎片，但场景
中彼此断开的石块、树木或道具仍保留不同的资产 ID 和 Part-ID。

场景模式会把候选交给最小且最具体的兼容对象根；已经被选为对象根的蒙版不能再
作为地面层的子部件。宽泛地面只负责接收尚未被独立对象认领的像素。因此角色、
道具、岩石和树木不会因为落在同一地面上就被合并为一个 ID。
对于双画板式场景，算法会闭合背景环上的小缺口，恢复环内对象轮廓，并删除过于矩形
的重复画板填充。该步骤依据连通性、包围关系和多候选一致性，不使用测试图坐标。

自动模式不会强行为每个未知结构猜一个自然语言名称。语义证据不足时，精细诊断层
可以保留 `visual_panel`、`visual_strip` 或 `visual_detail`，但它们不能仅凭颜色或
纹理成为公开编辑组；快速场景模式统一发布独立的 `scene_object`，避免把临时类别
伪装成已验证语义。

自动模式还可以加载人工审核的对象—部件原型索引。系统先检索相似对象，再从相似
样本中恢复常见部件清单、别名、外观原型和归一化位置先验；候选仍须经过
Grounding DINO、SAM2 与 HPID 融合验证。新增一批角色、道具或场景后，只需更新
审核数据并重建索引，不需要针对每张测试图修改代码。低于开放集阈值的未知对象不会
被强行套用最近类别。训练清单和命令见
[docs/RETRIEVAL_LEARNING.md](docs/RETRIEVAL_LEARNING.md)。

### 提示词模式

用户输入部件词，例如：

```text
stock=buttstock|rear stock, magazine, receiver, trigger, front sight
```

提示词模式优先使用 SAM3 文本概念分割。SAM3 负责把短语变成语义掩码，SAM2
自动区域负责补漏，HPID-Split 负责冲突处理、层级、所有权和 ID。SAM3 权重需要
先在 Hugging Face 页面接受条款并登录：

```powershell
hf auth login
```

模型页面：<https://huggingface.co/facebook/sam3>

程序不会在 SAM3 不可用时用 CLIP 相似度硬猜部件名称。默认 `auto` 后端会明确
降级到 Grounded-SAM2，并在状态行和诊断文件中记录；使用
`--guided-backend sam3` 可强制要求 SAM3。

## 快速安装

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[foundation,ui]"
hpid-split-web
```

浏览器打开 `http://127.0.0.1:7860`。

- `Primary asset`：只拆分画面中的主资产；
- `Entire scene`：拆分画面中的场景层和多个资产根；
- `Fast`：复用一次 SAM2 候选池，并运行轮廓补充、跨证据融合和受限边缘细化；
- `Ensemble`：运行更完整的检测与语义候选栈，速度明显更慢；
- `Complete hidden regions`：启用证据门控的遮挡区域补全。

`Entire scene + Fast` 优先保证每个对象拥有独立轮廓和 ID，所有自然语言场景标签
都会标记为待复核；需要场景对象语义时使用 `Ensemble`，由其运行 SigLIP 2 场景
本体共识。两种模式不会把低置信标签伪装成已验证结论。

隐藏区域补全需要额外安装 LaMa 适配器：

```powershell
hpid-split setup-completion
```

## 当前跨类别回归

本轮开发机记录的 Fast 核心流水线阶段耗时如下，不含导出与包验证：

- 护目镜角色：34.60 秒，18 个精细 Part、7 个编辑组；
- T-pose 角色：36.62 秒，15 个精细 Part、6 个编辑组；
- 刀具：`Fast` 35.78 秒，15 个精细 Part 融合为刀刃、刀柄和缠布 3 个物理组；
- 枪械：`Fast` 32.23 秒，15 个精细 Part 融合为 7 个物理编辑组；
- 地球仪：`Fast` 39.42 秒，7 个精细 Part 融合为 4 个物理组；
- 岩石游戏场景：`Fast` 27.85 秒，22 个精细 Part、22 个独立组；
- 双建筑场景：`Fast` 25.17 秒，6 个精细 Part、6 个待复核场景组。

这些数据包均通过结构、层级、前景守恒、字节数、逐文件 SHA-256 重算和
`ground_truth_used=false` 校验。数量与耗时
会随图像、显卡、模型缓存和所选路径变化，只能证明执行和结构一致性，不能作为语义
准确率或公开基准结果，部件越多也不等于结果越好。当前角色回归能够统一身体、上衣
与袖子，并把被过宽头发掩码覆盖的面部皮肤归还给身体组；所有闭合操作都会裁回原始
前景。这仍不代表算法对任意角色或任意类别都能零错误拆分。
精确来源哈希、运行编号和已知复核项记录在
[`benchmarks/cross_domain_structural_regression_v0.7.json`](benchmarks/cross_domain_structural_regression_v0.7.json)。

## 输出内容

每次运行会导出：

- `part_id_map.tiff`：无损实例 ID 图；
- `parts.json`：语义、父子关系、装配父级、边界框和补全状态；
- `group_id_map.tiff`、`groups.json`：保守的物理编辑组与成员 Part ID；
- `group_id_preview.png`、`group_overlay.png`：网页默认显示的编辑组和边缘叠加；
- `masks_visible/`、`crops/`：逐 ID 可见掩码与透明裁片；
- `masks_full/`、`crops_completed/`：可选的隐藏区域推断结果；
- `candidates.json`、`candidate_masks/`：候选证据与掩码；
- `inference_diagnostics.json`：模型、路由、拒绝原因和融合诊断；
- `package_manifest.json`：文件 SHA-256 与算法来源。

## 不能夸大的部分

- 隐藏区域是模型生成的可审计假设，不是真实内部结构、物理深度或三维重建；
- 当前跨类别图片没有像素级人工标注，因此尚无跨类别 mIoU/Boundary F1；
- 自动模式可能漏掉低对比度、极小或严重遮挡的部件，`Fast` 优先稳定性和速度；
- 当前护目镜角色中的低对比度侧包会在自动 Fast 模式中省略，因为现有检测掩码同时
  覆盖了上衣；`character_bag` 仍可在提示词模式中使用更严格的面积门。双建筑场景中，
  贴近建筑的展示台或阴影仍可能并入对象轮廓，二者都必须标记为待复核；
- SAM3 正式权重在本机尚未获授权，当前只用公开随机微型模型验证了真实 API
  调用链，不能据此声称提示词分割质量；
- Grounded-SAM2 降级链能运行并保留自动结构，但 AK 冒烟测试的 10 个提示词中
  没有一个同时通过歧义门和独立稠密语义证据门，因此未强行写入错误语义；
- 证据不足时算法会在精细诊断层保留通用视觉 ID、把公开组降级为中性名称，或拒绝补全；这属于预期行为。

算法细节见 [docs/ALGORITHM.md](docs/ALGORITHM.md)，输出契约见
[docs/OUTPUT_FORMAT.md](docs/OUTPUT_FORMAT.md)，第三方许可见
[THIRD_PARTY.md](THIRD_PARTY.md)。
